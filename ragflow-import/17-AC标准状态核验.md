> 是「官方来源」一栏的依据出处。

## 一、为什么要核验

目录库卡片最初只根据**标准名称**推断适用性，`官方来源` 一栏写的是「未核验」。
这带来两个问题：

1. 助手无法判断某个标准**是否仍然有效**——已废止的标准被当现行推荐，是会误导办案的。
2. 验收用例（AC-01～AC-16）的核心判定项包含「主推荐标准」，
   而状态未核验时按规则一律不得作为主推荐，用例根本无法按设计判定。

| 全国标准信息公共服务平台（行标） | GA/T、SF/Z 等 | `std.samr.gov.cn/hb/search/stdHBDetailed?id=<id>` |

核验项：**标准状态、发布/实施日期、替代关系、详情页 URL**。
状态一律以发布机构详情页为准，不从名称或年份推测。

## 四、回写内容

核验结果已回写 `06-标准总目录候选.jsonl`，每条新增六个字段：

| 字段 | 含义 |
| --- | --- |
| `source_url` | 发布机构详情页 URL |
| `published_date` / `effective_date` | 发布 / 实施日期 |
| `supersedes` | 被本标准代替的旧版编号 |
| `verified_date` | 核验日期 |
| `verified_note` | 核验备注（如「全部代替 2012 版」） |

同时回写 `status`：`待权威核验` → `现行` / `废止`。

> `body_status`（正文状态）、`review_status`、`primary_recommendation` 三个字段**未动**——
> 它们属于另一条线（正文取得与否），不由本次状态核验决定。
