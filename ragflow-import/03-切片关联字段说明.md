# 正文切片关联格式

明细文件 `03-正文切片关联.jsonl` 每行一个切片，用于把 RAGFlow 中的每个切片
关联回标准、章节、源文件与哈希。该文件包含条款原文，因此**只保留在本地，
不进入仓库**；本文件说明其字段与外层工具如何消费它。

## 字段

| 字段 | 说明 |
| --- | --- |
| `chunk_id` | 切片标识，形如 `<document_id>::chunk-001` |
| `document_id` | 文档标识，来自标准编号的小写形式 |
| `standard_id` | 标准编号，如 `SF/Z JD0400001-2014` |
| `version` | 版本年份 |
| `status` | 标准生命周期状态 |
| `review_status` | 复核状态 |
| `section` | 切片覆盖的章节/条款标题，**含条款文本，故不公开** |
| `source_line_start` / `source_line_end` | 在源 Markdown 中的行号范围 |
| `source_markdown` | 源 Markdown 相对路径 |
| `source_pdf` | 原始 PDF 相对路径 |
| `sha256_pdf` / `sha256_markdown` | 原始 PDF 与转换物的哈希 |
| `text_chars` | 切片文本字符数 |
| `sha256_chunk_text` | 切片正文的哈希 |

## 结构示例

`section` 字段已用占位文本替换：

```json
{"chunk_id": "sf-z-jd0400001-2014::chunk-001", "document_id": "sf-z-jd0400001-2014", "standard_id": "SF/Z JD0400001-2014", "version": "2014", "status": "推荐适用", "review_status": "人工复核后可导入", "section": "<章节标题>", "source_line_start": 1, "source_line_end": 40, "source_markdown": "ragflow-import/01-正文Markdown/<文件名>.md", "source_pdf": "<本地路径>/<文件名>.pdf", "sha256_pdf": "<64 位十六进制>", "sha256_markdown": "<64 位十六进制>", "text_chars": 1270, "sha256_chunk_text": "<64 位十六进制>"}
```

## 使用方式

`01-RAGFlow导入清单.md` 约定：上传 `01-正文Markdown-清洗版/`，
把 `02-元数据卡片.jsonl` 与 `03-正文切片关联.jsonl` 作为**外部关联索引**，
不把 JSONL 当作正文上传。

`validate_import.py` 会校验该文件的 `chunk_id` 唯一性、
与元数据中 `chunk_ids` 的一致性，以及切片行号是否落在源 Markdown 范围内。
