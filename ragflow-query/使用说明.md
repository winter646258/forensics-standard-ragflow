# 电子取证标准查询 · 使用说明

一个跑在本机的标准查询页面：输入问题 → 返回**基于标准原文生成的回答** + **命中的标准条款依据**。

- 后端接的是本机已有的 RAGFlow 知识库（正文库 15 份 / 424 切片 + 目录库 87 份）
- 纯 Python 标准库实现，**不需要 pip 安装任何东西**
- 只用本机资源，不联网、不上传

---

## 一、启动

**双击 `启动查询.bat`** 就行。

它会自动完成三件事：

1. 检查 Python 是否可用（没有会提示装）
2. 检查知识库是否在线；**不在线就自动调起 Docker Desktop** 并等 45 秒
3. 启动服务并自动打开浏览器

看到命令行窗口里出现这样一段，就是好了：

```
========================================================
  电子取证标准查询 已启动
  地址：http://127.0.0.1:8899/
  停止：在本窗口按 Ctrl+C
========================================================
```

> **别关那个黑窗口** —— 它就是服务本身。用完关掉窗口即可停止。

### 手动启动（备用）

```bat
cd /d "本目录路径"
python app.py --open
```

## 二、怎么用

1. 在输入框里写问题，比如「电子数据搜索检验记录表应该怎么填？」
2. 按 **Enter** 或点「查询」（Shift + Enter 是换行）
3. **右侧「引用来源」通常 1 秒内先出来**，左侧「回答」约 10～60 秒后出来

页面上方有 4 个示例问题，点一下就能直接查。

### 时间预期（实测）

| 环节 | 实测耗时 |
|---|---|
| 引用检索 | 0.3 ～ 0.7 秒 |
| 生成回答 | 18 ～ 59 秒（平均约 33 秒） |
| 与标准无关的问题 | 0.4 秒（直接拒答） |

回答慢是因为要经过检索 → 重排 → 大模型生成三步，不是卡住了。

## 三、引用来源怎么读（重要）

引用卡片上有两个标签，**含义完全不同**：

| 标签 | 含义 | 能不能当条款依据 |
|---|---|---|
| **正文库** | 标准正文全文，按条款切分 | ✅ 可以，能定位到条 |
| **目录库** | 只有标准编号、状态、替代关系 | ❌ **不能**，它根本没有正文 |

页面底部会有一行黄色提醒，说明目录库条目不含正文条款。

这样设计是刻意的：目录库用来回答「这个标准还在不在、被谁替代了、该用哪个」，
正文库才用来回答「第几条怎么规定的」。**混用会编出听起来很合理但不存在的条款。**

### 卡片上的数字

- **相似度**（0～1）：命中程度，实测集中在 0.4 ～ 0.6
- 点卡片可以**展开原文全文**
- 卡片标题下方的细条是相似度可视化

## 四、遇到问题

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 顶栏「RAGFlow 离线」 | Docker 或容器没起来 | 打开 Docker Desktop，等 RAGFlow 容器变绿 |
| 顶栏「凭据 缺失」 | 取不到 RAGFlow 的 API Key | 见下方「配置」一节 |
| 回答报 `EmbeddingError` | embedding 服务偶发抖动 | **应用已自动重试 2 次**，一般会自己恢复；连续失败再重启容器 |
| 页面打不开 | 端口被占了 | 应用会自动改用 8900、8901…；看黑窗口里的实际地址 |
| 回答很慢（>90 秒） | 首次调用或模型负载高 | 等一下；仍不动就重启应用 |

### 手工重启知识库（最后手段）

```bat
docker restart docker-ragflow-cpu-1
```

约 60 秒后恢复。**注意**：正常抖动靠自动重试就够了，不必动不动重启。

## 五、配置（`config.json`）

改完**要重启应用**才生效。

```jsonc
{
  "port": 8899,                  // 端口，被占会自动往后找
  "base_url": "http://127.0.0.1:8081/api/v1",
  "chat_id": "92eef474…bbbc",     // 绑定了双库的助手
  "dataset_ids": ["正文库id", "目录库id"],
  "token": "",                   // 留空则自动从 MySQL 取，一般不用填
  "retrieval": {
    "page_size": 8,              // 引用返回几组
    "similarity_threshold": 0.1, // 调高 = 更严，命中更少
    "vector_similarity_weight": 0.3
  }
}
```

### 关于 Token

按这个顺序找，找到就用：

1. `config.json` 里的 `"token"`
2. 环境变量 `RAGFLOW_API_TOKEN`
3. **从 Docker 里的 MySQL `api_token` 表读** ← 默认走这条

所以正常情况下不用管它。**不要把 Token 写进 `config.json` 再分享出去**。

## 七、已知限制

1. **回答里可能出现错的标准名配对。** 底层目录数据存在编号冲突
   （`SF/Z JD0402001-2015` 与 `SF/Z JD0402002-2015` 都叫「数据库数据真实性鉴定规范」），
   模型偶尔会张冠李戴。**条款必须以正文库引用的原文为准。**
2. **回答里会带 `（ID: 3 至 ID: 9）` 这类标记**，是助手提示词留下的，不影响阅读。
3. ~~**目录库里的数据比卡片文件旧**，`GA/T 2160-2024`、`GA/T 825-2009` 等新增条目还没重新上传。~~
   已于 2026-09-19 全量重建（87 张卡片），新增条目与核验后的状态都已入库。
4. **多数候选标准仍标「待权威核验」**（64/78），这类条目不能当主推荐依据。
5. **重要判定请人工复核** —— 这是辅助检索工具，不是标准权威解释。

## 八、验收结论

6 条端到端用例（含 1 条无关问题）实测：

- 引用检索 **6/6 成功**，平均 0.5 秒
- 回答生成 **6/6 成功**，平均 32.5 秒
- 无关问题正确拒答，且**不编造内容**（0 引用 + 16 字拒答）

明细见 `logs/验收记录.md`。

想自己重跑一遍（需要服务已在运行）：

```bat
python accept_query.py
```

报告默认**脱敏**：只写标准编号、条款号、相似度与判定结果，不含条款原文。
要把原文也留在本地时加 `--with-clause-text`，那份**不要提交到仓库**。
